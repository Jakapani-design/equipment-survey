# สำรวจอุปกรณ์สาขา — GitHub Pages + Google Sheets

หน้า HTML ทำงานบน GitHub Pages และอ่าน/บันทึกชีตผ่าน Google Sheets API โดยตรง ไม่เปลี่ยนหน้าไป Apps Script

## ไฟล์
- index.html: ตารางสำรวจ 93 สาขา แถบอุปกรณ์ 17 รายการ ช่องกรอกแบบย่อ และเลือกหลายสาขา
- config.js: OAuth Client ID แบบสาธารณะ และ Spreadsheet ID ของชีตเดิม
- sheets.js: Google sign-in, อ่านข้อมูล และบันทึกเป็นชุด
- .nojekyll: ใช้ไฟล์ static บน GitHub Pages

ไม่มี client secret, API key, token หรือข้อมูลสาขาฝังใน repository โทเค็นอยู่ในหน่วยความจำของหน้าเว็บและหายเมื่อปิดหรือโหลดหน้าใหม่

## การใช้งาน
1. เปิดเว็บไซต์ GitHub Pages แล้วกด เชื่อมต่อ Google
2. ลงชื่อเข้าใช้ด้วยบัญชีผู้ทดสอบที่มีสิทธิ์แก้ไขชีตเดิม แล้วตรวจสอบและอนุญาตสิทธิ์ Google
3. เลือกอุปกรณ์และสาขา กรอกจำนวน ผู้สำรวจ วันที่ และเหตุผลเมื่อจำนวนมากกว่า 1
4. กด บันทึก ในแถว หรือ บันทึกสาขาที่เลือก เพื่อบันทึกหลายสาขาในคำขอเดียว
5. กด โหลดข้อมูลใหม่ เพื่ออ่านการเปลี่ยนแปลงจากชีต ถ้ามีฉบับร่างจะถามก่อนทิ้ง

## Google ที่ตั้งค่า
- Project: Equipment Survey / smooth-research-512509-a1
- OAuth type: Web application
- Authorized JavaScript origin: https://jakapani-design.github.io
- OAuth อยู่ใน Testing ต้องเพิ่มอีเมลผู้ใช้ใน Audience > Test users และให้สิทธิ์แก้ไข Google Sheets แก่ผู้ใช้รายนั้น
- เปิด Google Sheets API ในโปรเจกต์ ไม่ต้องเปิด Billing หรือสมัคร Free Trial
- ขอ scope spreadsheets เพื่ออ่านและแก้ไขชีต Google จะแสดงขอบเขตสิทธิ์ก่อนอนุญาต โค้ดแอปนี้ระบุชีตเป้าหมายคงที่ แต่ OAuth scope ไม่ได้จำกัดเฉพาะชีตเดียว

## ขอบเขตและการทำงานพร้อมกัน
- ตรวจข้อมูลล่าสุดก่อนเขียน หากแถวต่างจากตอนโหลดจะปฏิเสธให้โหลดใหม่
- การตรวจและเขียนเป็นคนละคำขอ จึงไม่รับประกันป้องกันการเขียนทับหากมีคนแก้ไขระหว่างสองคำขอนี้ ควรแบ่งอุปกรณ์หรือสาขาให้ผู้สำรวจรับผิดชอบแยกกัน
- การบันทึกหลายแถวส่งเป็น batchUpdate หนึ่งชุด และอ่านผลกลับ ไม่มีการส่งซ้ำอัตโนมัติหากเครือข่ายขัดข้อง ให้ตรวจชีตก่อนลองใหม่
- เหตุผลและข้อความเขียนเป็น stringValue เพื่อให้ข้อความที่ขึ้นต้นด้วย = เป็นข้อความ ไม่ประมวลผลเป็นสูตร
- ไม่แก้คอลัมน์สถานะ H หรือสูตรหน้าสรุป บันทึกเฉพาะ C:G
- รองรับแท็บเดิมและแถว 6–98 หากเพิ่มสาขาหรือเปลี่ยนชื่อแท็บต้องปรับโค้ด

## เผยแพร่
อัปโหลดไฟล์ทั้งหมดไว้ที่รากของ repository จากนั้น Settings > Pages > Deploy from a branch > main > /(root)

## ตรวจสอบ
ทดสอบ syntax และ API adapter ด้วย Google response จำลอง: การเข้าสู่ระบบ จำนวนเต็ม 0 เหตุผล วันที่ การตรวจแถวที่เปลี่ยน การบันทึกหลายแถวในชุดเดียว ข้อความคล้ายสูตร และสิทธิ์หมดอายุ
การทดสอบจำลองไม่ยืนยันว่า Google OAuth และการบันทึกบนเว็บจริงทำงาน ต้องตรวจบนโดเมนที่เผยแพร่หลังผู้ใช้อนุญาตสิทธิ์
